# ACE UI 设计语言 · 1.0

ACE UI 的核心是熟悉的秩序：面向长时间使用的工作台，让内容、状态与行动保持清晰。视觉由石墨底、细边界、轻量线性图标和克制的强调色组成。它适用于管理后台、AI 工作空间、基础设施面板、工具应用与移动 WebView。

## 独立且一致的视觉语言

ACE UI 将紧凑工作台、对话工具、状态面板和移动布局统一为同一套规则。默认使用石墨深色，所有项目共享组件结构、语义变量、线性图标和交互行为。

## 颜色：同一语义，四套映射

- `dark` 石墨深色：默认皮肤，`bg #15181b`、`sidebar #101316`、`surface #1b1f22`、`accent #00f09a`。
- `light` 清透浅色：`bg #f7f9fc`、`surface #ffffff`、`accent #2560c8`。
- `sage` 豆沙绿：`bg #f2f6f3`、`surface #fbfdfb`、`accent #4a755c`。
- `eye` 深绿护眼：`bg #06100c`、`surface #0a1a12`、`accent #4cc47b`。

「护眼」沿用来源项目主题名称，表示低饱和、偏暖的视觉偏好。它不是医疗效果承诺。

品牌强调 `accent` 用于当前导航、重点图标、焦点和图表；主按钮使用 `action` 与 `on-action`，二者不能用强调色随意替代。成功、警告、错误、信息分别使用独立语义色。状态不能仅靠颜色表示。

`surface-hover` 表达悬停与次级容器，`field` 表达输入区域，`border` 为装饰分界，`border-strong` 用于控件边界。`text-muted` 只作非关键信息，主要说明用 `text-secondary`。

## 尺度与排版

| 项目 | 数值 | 用法 |
| --- | --- | --- |
| 基础网格 | 4px | 所有间距尽量为 4 的倍数 |
| 常用间距 | 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48px | 图标间距 8，字段 12，卡片 16–24，章节 24–32 |
| 控件高度 | 28 / 36 / 44px | 紧凑 / 标准 / 大号；粗指针主控件提升到 44px |
| 控件、卡片、弹窗圆角 | 4 / 8 / 12px | 三个尺度稳定复用，不按主题变化 |
| 图标 | 16 / 18 / 20 / 24px | 辅助 / 常规 / 导航 / 展示；24×24 源坐标 |
| 侧栏 / 顶栏 | 232 / 64px | 固定桌面骨架 |
| 正文最大宽度 | 1440px | 极宽屏不无限拉伸阅读区 |
| 页面边距 | 桌面 32 / 平板 24 / 手机 16px | 内容宽度与密度自适应 |
| 字号 | 12 / 13 / 14 / 16 / 20 / 28 / 36px | 从说明到展示标题的统一层级 |
| 字重 | 400 / 500 / 600，标题可 650 | 不通过过多字重制造层级 |
| 行高 | 1.6，长中文段落 1.8–1.9 | 交互控件不压缩中文阅读空间 |

首选 Inter / Segoe UI / PingFang SC / Microsoft YaHei，系统缺失时降级。包内不下载字体。数字、时间、资源 ID、日志和代码使用 Cascadia Code / SFMono / Consolas 等宽字体。

10px 英文眉题仅作辅助识别，不承载唯一重要信息。页面标题、面板标题、字段标签、辅助说明严格分层。

## 页面语法

桌面：侧栏 → 顶栏面包屑 → 页面眉题与主标题 → 一句说明 → 主行动 → 面板与列表 → 页脚。章节、卡片内外边距不混用。左右主次分栏常用 2.1:1，详情页采用 280px 主列表 + 自适应详情。

在 960px 以下优先堆叠次栏；760px 及以下侧栏收为展开导航；640px 及以下正文单列。四指标可保留两列。表格窄屏在容器内横向滚动，禁止整页横向滚动。原生移动模式采用底栏并预留 env(safe-area-inset-bottom)。

## 交互语法

控件均需考虑默认、悬停、聚焦、按下、禁用、加载。焦点环 2px、外偏移 3px；异步任务显示忙碌，防止重复触发。每个操作区域仅有一个主行动。返回或取消使用次按钮，破坏操作使用危险语义并确认。

hover 140ms、展开 200ms，统一 ease。常规卡片只靠 1px 边界建立层级；阴影用于对话框、菜单与消息浮层。遵循减少动画偏好。

## 文案与可访问性

按钮用动词加对象，例如「创建项目」「保存设置」。空状态说明为什么为空并给出下一步；错误说明原因与恢复方式，避免只写「失败」。示例数据、未接入 API 的操作必须明确标识。

输入有可见标签和必要的描述关联；Tabs 可方向键切换；Dialog 支持 Escape、焦点限制与关闭后恢复；所有图标按钮有可读名称；状态同时显示图标或文字；移动触摸目标至少 44px。关键正文目标 4.5:1，大字 3:1；应用扩展时需重新检查对比度。

## 扩展边界

新增组件先寻找现有结构；新业务状态先映射语义变量；需要额外色值时在 tokens 中集中定义。不要在业务组件散写硬编码颜色，也不要为四皮肤复制四份组件。不得把主题配色升级成四套布局、字号或图标样式。
